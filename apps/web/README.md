# web

The frontend: Vite + React 19 + TypeScript, styled with [shadcn/ui](https://ui.shadcn.com) on Tailwind CSS v4.

| Concern     | Library                                                     | Docs                                            |
| ----------- | ----------------------------------------------------------- | ----------------------------------------------- |
| Routing     | React Router (data mode)                                    | https://reactrouter.com                         |
| Server data | TanStack Query                                              | https://tanstack.com/query/latest               |
| Forms       | react-hook-form + zod                                       | https://react-hook-form.com, https://zod.dev    |
| UI          | shadcn/ui (Radix), lucide icons, sonner toasts, next-themes | https://ui.shadcn.com/docs                      |
| Tests       | Vitest + Testing Library                                    | https://vitest.dev, https://testing-library.com |

## Scripts

```bash
npm run dev -w web          # http://localhost:3001 (the API must be running for data)
npm run test -w web         # vitest run
npm run test:watch -w web
npm run lint -w web
npm run build -w web
```

In dev, requests to `/api/*` are proxied to the API at `http://localhost:3000/*`. To point them somewhere else, set `API_URL`, for example `API_URL=http://localhost:3010 npm run dev -w web`.

## Folder structure

```
src/
├── app/                  # app wiring: router, providers, layouts
│   ├── router.tsx        # ← all routes are registered here
│   ├── providers.tsx     # QueryClient, theme
│   └── layouts/          # shared page chrome (header, nav, <Outlet />)
├── components/
│   ├── ui/               # shadcn components (generated by the CLI; edit only when you mean to)
│   └── *.tsx             # our own shared components (e.g. mode-toggle)
├── features/<feature>/   # everything for one domain area, e.g. features/links
│   ├── api.ts            # query keys + useQuery/useMutation hooks
│   ├── schemas.ts        # zod schemas for forms
│   ├── components/       # components used only by this feature (+ *.test.tsx next to them)
│   └── pages/            # route components
├── pages/                # pages not tied to a feature (home, 404, error)
├── lib/                  # framework-free helpers (api-client, cn)
└── test/setup.ts         # Vitest setup
```

Import from `src` with the `@/` alias (`import { Button } from '@/components/ui/button'`). Inside a feature, use relative imports (`../api`). Shared API types come from `@repo/api`; always use `import type { Link } from '@repo/api'`.

`features/links` is the reference implementation. When in doubt, copy it.

## How to…

### Add a page

1. Create the component, e.g. `src/features/games/pages/games-page.tsx`, and export it as a named function: `export function GamesPage() {}`.
2. Register it in `src/app/router.tsx` under the `children` of the root route: `{ path: 'games', element: <GamesPage /> }`.
3. To add it to the navigation, add it to `navItems` in `src/app/layouts/root-layout.tsx`.

To navigate, use `<Link to="/games">` or `useNavigate()` from `react-router`. To read URL params, use `useParams()`.

### Add a shadcn component

Run this inside `apps/web`:

```bash
npx shadcn@latest add tabs
```

It writes `src/components/ui/tabs.tsx`. Browse the available components at https://ui.shadcn.com/docs/components.

### Fetch data from the API

Add hooks to the feature's `api.ts`, using `apiFetch` from `@/lib/api-client`:

```ts
export const gameKeys = { all: ['games'] as const };

export function useGames() {
  return useQuery({ queryKey: gameKeys.all, queryFn: () => apiFetch<Game[]>('/games') });
}
```

After a mutation succeeds, invalidate the related keys so lists refresh. Failed mutations show an error toast automatically; this is set up in `providers.tsx`. See `features/links/api.ts` for the full create/update/delete pattern.

Never call `fetch` inside `useEffect`. Use a query hook instead.

### Build a form

1. Write a zod schema in the feature's `schemas.ts`. Mirror the backend DTO; the backend's validation is the source of truth.
2. Call `useForm({ resolver: zodResolver(schema) })`.
3. Render shadcn `Field` / `FieldLabel` / `Input` / `FieldError` components.

`features/links/components/link-form.tsx` shows the whole pattern.

### Write a test

Put `*.test.tsx` next to the component it tests. `describe`, `it`, `expect` and `vi` are globals. Use `screen.getByRole` / `getByLabelText` and `userEvent`; see `link-form.test.tsx`. To test pages, render them through `createMemoryRouter(routes)`, as `app/router.test.tsx` does.

## Formatting

Prettier sorts Tailwind classes automatically (`prettier-plugin-tailwindcss`), and the pre-commit hook formats staged files. To format everything by hand, run `npm run format` from the repo root.
